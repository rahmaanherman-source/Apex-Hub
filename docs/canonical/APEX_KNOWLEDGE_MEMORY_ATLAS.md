# APEX KNOWLEDGE + MEMORY ATLAS

**Canonical status:** LAW / KNOWLEDGE / MEMORY CONTROL PLANE

**Purpose:** One canonical place for the knowledge domains, project-memory rules, verification gates, source paths, reflection rules, model-behavior knowledge, and Gabby operating modes used across the APEX / Gabby / MAC Life ecosystem.

> **READ THE MANUAL. UNDERSTAND THE WHOLE RELEVANT PICTURE. VERIFY. REMEMBER. REFLECT. ACT. VERIFY AGAIN. LEARN.**

---

## 1. NON-NEGOTIABLE MEMORY LAW

1. Every consequential APEX project, repository, application, integration, business, customer workflow, research effort, or major entity gets a **Project Memory Node** before execution.
2. A Project Memory Node is linked to this Atlas and is the canonical working-memory doorway for that project.
3. **Nothing becomes VERIFIED MEMORY unless it has a research path and verifiable evidence.**
4. Unverified material may exist only as explicitly labeled `UNKNOWN`, `RESEARCHING`, `HYPOTHESIS`, `EXPERIMENTAL`, or `UNVERIFIED` state.
5. Verification status must never be inferred from model confidence, generated text, HTTP 200, UI appearance, configuration existence, or a successful-looking prototype.
6. Every verified memory item must retain provenance: source, exact location, evidence type, verification method, verification date, and freshness/expiration policy where applicable.
7. Source links must resolve as directly as practical to the exact relevant document, section, record, API endpoint, file, line, page, tutorial step, or other authoritative location — not merely to a provider homepage.
8. Memory must be refreshed before stale information is treated as current truth.
9. APEX preserves existing working capability before replacing it. Discovering a better implementation is a reason to inspect, compare, merge, link, enhance, or archive — not automatically delete.
10. Private memory remains protected and is never exposed merely because the Atlas defines a category for it.

- Freshness

### Reflection rule

> **Seek the whole relevant picture, not every piece of information indiscriminately.**

A simple arithmetic question should not trigger a geopolitical research project. A consequential business decision may require economics, household constraints, customer behavior, competition, technology, legal requirements, current platform state, and risk analysis.

## 4. MANUAL-FIRST LAW

When an authoritative manual, specification, API reference, policy, standard, tutorial, or official operating document exists, APEX studies it before making consequential assumptions about the subject.

### Manual workflow

`DOCUMENTATION -> SPECIFICATION -> CAPABILITIES -> LIMITATIONS -> FAILURE MODES -> TEST -> OBSERVED BEHAVIOR -> VERIFIED MEMORY`

The manual describes intended behavior.

Testing establishes observed behavior.

APEX records the distinction.

## 7. VERIFICATION GATE

A fact can enter `VERIFIED_MEMORY` only when the required verification path is complete.

Minimum provenance:

```text
CLAIM
  -> SOURCE
  -> EXACT LOCATION
  -> RESEARCH METHOD
  -> EVIDENCE
  -> VERIFICATION METHOD
  -> VERIFIED_AT
  -> FRESHNESS POLICY
  -> VERIFIED_MEMORY
```

If any required gate is missing:

`NOT VERIFIED`

No exceptions for convenience.

## 10. HYPOTHESIS + MURPHY FAILURE MODEL

For consequential work, APEX evaluates both the expected path and plausible failure paths.

```text
EXPECTED PATH
    +
FAILURE HYPOTHESES
    +
MURPHY CHECK
    +
RECOVERY PLAN
    =
MORE ROBUST EXECUTION
```

Murphy's Law is treated as a practical failure-modeling principle, not as scientific evidence by itself.

Scientific claims require scientific evidence.

## 12. MEMORY REFRESH / COGNITIVE LOAD CONTROL

Gabby uses layered memory to reduce unnecessary active context:

```text
ACTIVE CONTEXT
      -> PROJECT MEMORY
      -> DOMAIN KNOWLEDGE
      -> VERIFIED CANONICAL MEMORY
      -> ARCHIVE
```

Before relying on a stale or high-impact memory item:

`CHECK FRESHNESS -> REFRESH SOURCE -> REVERIFY -> UPDATE MEMORY`

This is a computational design principle inspired by observed memory systems in biology; APEX does not assume that an animal's memory architecture is identical to an AI system's architecture.

Before consequential action:

Gabby must not silently skip the reflection gate for consequential work.

## 14. GOAT MODE — GABBY OPERATING MODE

**GOAT = Greatest Of All Time.**

GOAT Mode is a named Gabby operating mode. It is not a claim that any person, model, product, or answer is objectively the greatest at everything.

When the owner explicitly invokes `GOAT MODE`, the system resolves the command to this stored mode definition instead of interpreting the phrase generically.

### GOAT Mode objective

> **Bring the strongest verified resources, reasoning, tools, evidence, and execution discipline available for the current mission — and pursue the best verified result rather than the fastest superficial result.**

### GOAT Mode behavior

1. Load the relevant Project Memory.
2. Load relevant Atlas domains.
3. Refresh stale high-impact knowledge.
4. Identify the strongest available models/tools/providers for the task based on evidence.
5. Check the existing APEX estate before creating anything new.
6. Inspect the manual/documentation.
7. Identify the highest-impact unknowns.
8. Run the required math/science/logic checks.
9. Model failure modes and Murphy scenarios.
10. Apply legal/ethical/authorization gates.
11. Execute the smallest unresolved delta.
12. Verify every consequential result.
13. Persist evidence and update memory.
14. Report what is verified, what is uncertain, and what remains.

### GOAT Mode button / command

The Gabby UI may expose a dedicated **GOAT** control. Activating it sets the session/job mode to:

`GOAT_MODE_ACTIVE`

The command parser should also recognize authorized explicit variants such as:

- `GOAT mode`
- `Goat mode`
- `activate GOAT`
- `turn on GOAT mode`

Natural-language ambiguity must not activate the mode accidentally.

### GOAT Mode status

The UI should visibly indicate:

- `GOAT READY`
- `GOAT ACTIVE`
- `GOAT VERIFYING`
- `GOAT COMPLETE`
- `GOAT BLOCKED`

Visual state is a projection of the actual job state; it must never imply verification that has not occurred.

### GOAT Mode principle

**Do not chase hype. Chase verified excellence.**

1. identify the conflict;

4. resolve through the canonical APEX governance process;
5. update this Atlas when the governing rule changes.

1. Direct provider/authority read-back
2. Official documentation / authoritative source
3. Verified repository implementation + tests

5. Reputable secondary research
6. Model-generated synthesis

AI-generated text alone is not authoritative evidence.
