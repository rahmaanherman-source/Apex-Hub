# APEX CANONICAL MEMORY SLAB

**STATUS:** CANONICAL MEMORY SEED
**AUTHORITY:** APEX-Laws

## MEMORY RULE

KEEP WHAT MATTERS.
MERGE WHAT'S THE SAME.
ADD WHAT'S NEW.
LINK WHAT'S CONNECTED.
LEAVE THE REST IN THE ARCHIVE.

## VERIFIED EVOLUTION LOOP

```text
PRESERVE
→ ADD
→ INTEGRATE
→ TEST
→ VERIFY
→ COMPOUND
```

Every verified improvement becomes part of the next capability baseline.

```text
CURRENT VERIFIED APEX
+
VERIFIED IMPROVEMENT
=
NEXT APEX BASELINE
```

Never silently subtract an existing verified capability.

## MEMORY / TRUTH SEPARATION

- Memory = durable operating knowledge.
- Evidence = proof supporting a claim.
- Audit = examination of current state.
- Archive = historical source material.
- Truth = a state established through evidence and verification.

Do not promote assumptions into memory as facts.

## CANONICAL EXECUTION RECALL

Every governed system should be able to recall:

```text
LOAD LAW
LOAD MEMORY
AUDIT CURRENT SYSTEM
COMPARE AGAINST LAW
COMPARE AGAINST MEMORY
IDENTIFY REGRESSION
IDENTIFY DUPLICATION
IDENTIFY GAPS
CLEAN UP
THEN BUILD
```

## CLEANING LAW

When multiple records express the same durable rule:

```text
KEEP THE STRONGEST VERIFIED FORM
MERGE DUPLICATES
LINK RELATED RULES
ARCHIVE SUPERSEDED SOURCE
RETAIN PROVENANCE
```

When a conflict exists:

```text
STOP
→ SURFACE CONFLICT
→ LOCATE AUTHORITY
→ COLLECT EVIDENCE
→ RESOLVE
→ TEST
→ VERIFY
→ PROMOTE
```

## APEX MEMORY BASELINE

1. Preserve verified capability.
2. Add verified capability.
3. Never treat documentation alone as proof.
4. Never treat a benchmark as APEX authority.
5. Never silently remove working controls.
6. Never allow duplicate laws to become competing authorities.
7. Keep canonical source locations explicit.
8. Keep evidence linked to the claim it proves.
9. Keep stale or superseded material in the archive rather than active memory.
10. Compound verified improvements into the next baseline.
