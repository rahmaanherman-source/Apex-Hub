# APEX CANONICAL MEMORY SLAB

**STATUS:** CANONICAL MEMORY SEED
**AUTHORITY:** APEX-Laws

## MEMORY RULE

KEEP WHAT MATTERS.
MERGE WHAT'S THE SAME.
ADD WHAT'S NEW.
LINK WHAT'S CONNECTED.
LEAVE THE REST IN THE ARCHIVE.

## VERIFIED EVOLUTION LOOP

```text
PRESERVE
→ ADD
→ INTEGRATE
→ TEST
→ VERIFY
→ COMPOUND
```

Every verified improvement becomes part of the next capability baseline.

```text
CURRENT VERIFIED APEX + VERIFIED IMPROVEMENT = NEXT APEX BASELINE
```

Never silently subtract an existing verified capability.

## MEMORY / TRUTH SEPARATION

- Memory = durable operating knowledge.
- Evidence = proof supporting a claim.
- Audit = examination of current state.
- Archive = historical source material.
- Truth = a state established through evidence and verification.

Do not promote assumptions into memory as facts.

## WHOLE-SYSTEM OPERATING MEMORY

For every AI-built system and every new subject it operates, remember that readiness means understanding the relevant whole—not merely the visible page.

Where applicable, active context includes:

- history
- science
- mathematics
- engineering
- culture and human dynamics
- system dynamics and dependencies
- analytics and measurement
- economics, business model, and monetization
- security, privacy, legal, and compliance
- architecture and integrations
- authoritative manuals and documentation
- navigation, workflows, limitations, edge cases, and failure modes
- established knowledge, proven methods, and leading expert work
- required tools, access, data, checks, and contingency paths
- current real-time state

## MANUAL-FIRST MEMORY

If a creation has an authoritative manual, help system, operating guide, API documentation, policy, or equivalent instructions, **read it first before operating whenever reasonably accessible.**

Remember what it teaches about navigation, intended behavior, constraints, permissions, failure modes, recovery, and changes. Do not wait for a preventable failure to discover information already documented.

Documentation is an operating input. Documentation alone is not proof of implementation.

## REAL-TIME APEX MEMORY

APEX readiness is continuously refreshed. Historical knowledge and documentation are combined with current state and live evidence.

```text
HISTORY + MANUAL + DOMAIN KNOWLEDGE + CURRENT STATE + LIVE EVIDENCE
= APEX OPERATING PICTURE
```

If a relevant condition changes during execution, re-check it. Do not operate from stale assumptions.

## CLEANING LAW

When multiple records express the same durable rule:

```text
KEEP THE STRONGEST VERIFIED FORM
MERGE DUPLICATES
LINK RELATED RULES
ARCHIVE SUPERSEDED SOURCE
RETAIN PROVENANCE
```

When a conflict exists:

```text
STOP
→ SURFACE CONFLICT
→ LOCATE AUTHORITY
→ COLLECT EVIDENCE
→ RESOLVE
→ TEST
→ VERIFY
→ PROMOTE
```

## APEX MEMORY BASELINE

1. Preserve verified capability.
2. Add verified capability.
3. Read authoritative manuals before operation whenever accessible.
4. Treat history, science, math, culture, dynamics, analytics, economics, and monetization as relevant whole-system context when applicable.
5. Compare substantive work against established knowledge and leading methods before operating.
6. Plan required tools and contingencies before consequential execution.
7. Combine historical understanding with current state and live evidence.
8. Never treat documentation alone as proof.
9. Never treat a benchmark as APEX authority.
10. Never silently remove working controls.
11. Never allow duplicate laws to become competing authorities.
12. Keep canonical source locations explicit.
13. Keep evidence linked to the claim it proves.
14. Keep stale or superseded material in the archive rather than active memory.
15. Compound verified improvements into the next baseline.
