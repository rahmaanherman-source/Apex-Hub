## 5. Audit Feed

The Audit Feed is the chain of custody for APEX operations. It must be:

- append-only
- hash-chained
- tamper-evident
- replayable
- idempotent
- queryable
- auditable
- evidence-producing

Canonical event families include:

`router.*`, `webhook.*`, `tx.*`, `ledger.*`, `payout.*`, `fx.*`, `registry.*`, `verification.*`, `identity.*`, `security.*`, `admin.*`, `model.*`

Important operations should record:

`event_id`, `timestamp`, `source`, `actor`, `action`, `event_type`, `resource`, `correlation_id`, `payload`, `evidence`, `hash`, `prev_hash`

Never store PAN, CVV, secrets, API keys, or unnecessary sensitive credentials in audit payloads.

## 7. Local-First Routing

Default execution is local. Cloud fallback is denied unless explicitly authorized.

Evaluate capability, modality, installation, health, enablement, license/commercial-use status, privacy classification, hardware capacity, VRAM, RAM, context requirements, latency, and task-specific benchmark evidence.

Hard policy failures eliminate a model rather than merely lowering its score.

## 8. GPU / VRAM Policy

Never guess hardware capacity. Probe the real machine.

Measure GPU vendor/model, VRAM total/free, driver, compute capability when available, temperature, utilization, RAM, disk, CPU, and runtime availability.

Use a safety reserve. A model must account for weights, KV/context memory, workflow overhead, media latent memory, and safety margin.

If it does not fit, consider a smaller verified model, lower quantization, lower context/batch, lower media resolution/duration, queueing, permitted CPU/offload, block, or authorized cloud escalation.

Never silently upload local data.

## 9. Cloud Escalation

A cloud adapter may not execute merely because local execution failed.

First produce `LOCAL_GAP_EVIDENCE`, then require:

- approved provider adapter
- data-egress assessment
- allowed data class
- cost estimate
- approval
- audit receipt

Use official APIs and legally distributed model weights only. No unofficial consumer-web automation or reverse-engineered API.

## 10. Adapter Contract

Every adapter identifies provider, adapter ID/version, execution scope, runtime, model, exact model version, digest where available, capabilities, modalities, resource requirements, license, commercial-use status, privacy class, health, benchmark evidence, endpoint, node, errors, and audit references.

Cloud adapters additionally identify allowed data classes, region, retention policy, approval requirement, cost policy, and egress policy.
